The active allocation uses `user_data/research/lesson-week-cloud-v2-approved/` on the original
operator computer. Earlier cancelled preparations are unfunded and must not be used.

GitHub Linux runner. It does not install the legacy trading runtime, use a paid runner or
publish plaintext research data. It makes no market or model request in `verify` mode.

The experiment was fixed before its future data: October 17–23, 2026 entry opportunities,
October 24 protective exits, scheduled October 25 at 06:30 UTC. Its scientific source,
lesson and protocol hashes are unchanged. GitHub schedules can be delayed or dropped.

copy retains historical records and is capped at 168 lifetime reservations. A persistent
remote Git ref claims the study before any market/model call; a duplicate or uncertain
claim cannot authorize another paid draw. Lost or uncertain usage keeps the full original
hold. Successful authenticated collection reconciles the original allocation once.

Required environment secrets in `jev-lesson-week`, restricted to develop:

- `JEV_RESEARCH_ENVELOPE_KEY`: base64 AES-256-GCM key, retained in a private host file.
- `TYPESAFE_API_KEY`: existing provider token; never include either value in Git or logs.

Only allowlisted Python sources, original lesson/evidence/receipts, protocol and funded
execution ledger enter the encrypted input. Git stores only ciphertext and public identities.
Results, journals and execution accounting are encrypted and committed to the dedicated
`research/lesson-week-v2-cloud-claimed` branch. No Actions artifacts/cache/Packages are used.
The scheduled workflow disables itself after its terminal execution attempt.

An isolated completion job mentions the owner in
[the completion issue](https://github.com/Daniel-eldick/neural-edge/issues/6) after the
execution attempt, including failure/cancellation. It has only issues-write permission,
no checkout or research secrets, and publishes only status and a run link. Verification,
early and skipped runs do not post. GitHub email/mobile delivery follows the owner's
notification settings. This alert can run while the operator computer is off.

Private delivery and its repository-scoped write key were explicitly approved by the owner.
The private summary is generated by a separate standard public-runner job, without any
model calls, and delivered to the owner's private `jev-research-results` repository,
branch `reports`. Its deploy key grants access only to that repository; the summary job
does not receive the TypeSafe token. GitHub's SSH host key is pinned, target privacy must
be checked before each write, and report/key text is captured rather than logged. Only
fixed prose and validated numerical metrics enter the report; original evidence stays
encrypted in the public source repository. Verification writes only `connection-check.md`.
The private report repo has Actions disabled and introduces no paid compute or storage.

The report compares completed trades, net profits/returns after simulated fees and
slippage, coverage and decision changes. It separates known settled inference costs,
uncertain reservations and the original host allocation. Limited coverage or an incomplete
comparison is inconclusive; one week cannot establish repeatable learning. Reading the

computer. The public completion alert links to it and includes delivery status only.

The existing local collector checks October 25–31 for the encrypted outcome, then stops
after a terminal summary or final check. It remains responsible for authenticating and
reconciling the original host ledger when the computer/app is available. The cloud report
cannot reconcile that ledger, release a hold or rerun the test. Frozen snapshot headroom

## One automatic post-test review

A separate `learning` job performs at most one pinned Jev review after this frozen test.
It uses a separate USD 0.003 hold funded through the original USD 3 monthly guard; the
existing USD 0.504 replay allocation and frozen input are unchanged. Its encrypted budget
copy preserves all prior records. An atomic learning claim prevents duplicate paid draws;
the copy allows exactly one USD 0.003 reservation, only in October before pricing expiry.

The job authenticates the original encrypted outcome before reviewing it. Fewer than ten
completed trades in either AI variant, failed evidence or no outcome means an inconclusive
record without a model call. With sufficient completed coverage, Jev selects a fixed
retain/revise/set-aside/inconclusive research stance. Numeric findings, actual receipt,
parent lesson identity, training cutoff and real availability time enter immutable private
`lessons/lesson-week-v2-review-v1.json` and `.md` files. No model weights, original lessons,
frozen test, trading policies or risk rules change. Improvement requires later unseen data.

The funded input bundle stays in two protected environment secrets, never the public repo;
each encoded part is below GitHub's per-secret size limit. The runner reconstructs it only
after verifying the public expected hash, then the controller authenticates its encryption,
source and original allocation. No funding or lesson text is printed in logs.

Learning input/results use separate authenticated encryption domains. The receipt, model
response store and execution ledger are encrypted in an immutable private receipt file;
the public learning claim contains only the already-public source revision, no learning data.
No private lesson text or cost is printed publicly. The original host hold stays until
authenticated local collection; uncertainty retains the full USD 0.003 learning hold.
A later candidate-push failure leaves its already-committed encrypted receipt collectible.
If the initial receipt push fails, runner cleanup can lose the only evidence copy. The claim
and full USD 0.003 hold then remain pending manual accounting; no automatic paid retry or
refund is allowed. A generic workflow failure is still reported.
Verification only checks its funded envelope and writes `learning-connection-check.md`,
with no model construction, claim, market request or lesson generation.

On the original operator computer, download the encrypted `result.enc` from that branch into
the ignored `user_data/research/lesson-week-cloud-v2-approved/` directory. Then, from the original local
research checkout:

```bash
.venv/bin/python -m deploy.research.cloud collect --directory user_data/research/lesson-week-cloud-v2-approved
```

Collection verifies the encryption, allocation, terminal report and execution ledger. It
imports authenticated failure evidence even if provider usage remains uncertain; in that
case the full original hold stays pending. It never calls the provider or reruns the replay.
The public repository's legacy source is not the frozen research runtime: the controller
restores that exact runtime from the authenticated encrypted snapshot before importing it.

For learning collection, read the private report repository's
`learning-receipts/lesson-week-v2-review-v1.enc.base64` on `reports`, base64-decode to the
ignored `user_data/research/lesson-week-learning-v1/learning.enc`, then run:

```bash
.venv/bin/python -m deploy.research.learning collect --directory user_data/research/lesson-week-cloud-v2-approved --funding user_data/research/lesson-week-learning-v1
```

This verifies original study evidence, rebuilds the saved candidate using cached responses,
and reconciles only the separate learning hold. Missing or uncertain proof retains it.

## Automatic adoption for future research

An unpaid `selection` job now follows the fresh comparison. It restores the same verified
runtime and funded input, authenticates private results, then reproduces all replay journals
from cached responses. It never constructs a provider client or alters/reconciles a budget.
The pinned rule in `promotion-rule/runner.json` was declared before the fresh entry window.

A candidate must have at least10completed trades in every Jev arm, positive net trading
profit, return at least0.10percentage points above original/frozen/baseline, and maximum
drawdown no worse than original/frozen and strictly below10%. Evidence must be complete,
without policy errors/open positions/unknown usage, and receipts must match within the
existing USD0.432 allocation. Otherwise the original lesson stays selected. This is
provisional research adoption, not evidence of repeatability or a real-trading permission.

`lesson-selection/decision-v1.enc.base64` and its private README record the verdict.
Only approval creates `lesson-selection/active.enc.base64`, atomically in the same commit.
A missing/corrupt result never enables a candidate. Existing versions cannot be overwritten.
The job has no TypeSafe token; adds no paid requests, escrow, secret, hosting or schedule.
A private connection check is the only verify-mode output. The completion notice links to
the private decision and reveals no metrics/lesson text. The original frozen experiments
continue their explicit fixed policies and original promotion_allowed=false contracts.

Future authorized research runs create their default policy with
`deploy.research.research_policy.make_research_policy(parent, store, recorder, api_key=...,
budget=..., key=..., now=..., max_attempts=...)`, after restoring the original research
runtime. `parent` must match the full pinned original LessonPack; the selector is read once,
verified and passed to unchanged LessonPolicy/JevClient. Every actual request still requires
the persistent monthly guard and the supplied per-run attempt limit. This increment starts
no new paid decisions or worker. Model weights/risk/exit rules are unchanged.

The exact tested payload is retained. Its training cutoff includes the validation period;
effective availability is at least the real private-selector retrieval completion. Earlier
observations fail before a model request. This conservative boundary applies even to a newly
created replay of dates after approval but before retrieval: freeze a new future window.
The encrypted `policy.selection_snapshot` is saved once in the private journal; checkpoints
carry only its SHA. For resume, pass that same persisted `selection_snapshot` to the factory.
It authenticates the snapshot, does not reread/switch current selection and preserves its
checkpoint identity. Missing selection uses original; invalid selection refuses.

Rollback requires explicitly removing the active pointer, preserving decision history and
original context. Disabling the selection job prevents new adoption. This is a single
candidate/version; a different validation/rule requires a separately authorized version.

new comparison uses November3–6 entries, November7 protective exits, and evaluation

funding, sources and the one-shot selector remain fixed.

Each weekly comparison runs independent baseline, frozen Jev, incumbent and candidate
accounts. At most48calls per AI arm; at most one teacher call reviewing the last completed

promote. A candidate needs the same declared10closed-trade/positive-profit/0.10pp/drawdown/

candidate's exact tested context becomes the next cycle's incumbent; otherwise keep the
incumbent. The loop's encrypted state is its active selector; the old one-shot factory is

The private `reports` branch holds `loop-v1/state.enc.base64`, per-week immutable encrypted
freezes/results, and `loop-v1/README.md` with completed trades, costs and verdicts. Existing

Budget authority is migrated once from the original local SQLite guard. The migration

including future months; existing escrow reconciliation still works. The encrypted remote
